1. Tổng quan dự án StockHub

Hệ thống quản lý nhập, xuất và luân chuyển hàng hóa đa kho cho doanh nghiệp với cơ chế phê duyệt tài chính một lần.

Ngày cập nhật: 21/11/2026 Hệ thống: ĐT07: StockHub (.NET 10 Web API + React 19 SPA) Trạng thái: Chỉ có spec, chưa sửa code Lịch sử quyết định: 21/11/2026 (Chốt 3 vai trò, duyệt link demo trực tiếp, Docker + CI + Code Coverage)
Kết luận nhanh:

Dự án giải quyết bài toán quản trị kho nhiều chi nhánh, kiểm soát chặt chẽ giá trị tồn kho và bất biến chứng từ. Trọng tâm cốt lõi là bảo vệ nghiêm ngặt 3 quy tắc bất biến: (1) Tồn kho không bao giờ âm; (2) Phiếu đã duyệt cấm chỉnh sửa/xóa; (3) Liên kết duyệt phiếu gửi Kế toán chỉ được sử dụng đúng 1 lần.

Hướng giải pháp: Backend .NET 10 Clean Architecture + CQRS (MediatR) + EF Core 10 (PostgreSQL/SQL Server) + Optimistic Concurrency Token; Frontend React (TypeScript + Vite + Tailwind CSS); Hỗ trợ Swagger JWT Bearer + Refresh Token; Đóng gói Docker Compose và kiểm thử tự động với GitHub Actions CI.

Bối cảnh & Mục tiêu nghiệp vụ

Doanh nghiệp phân phối hàng hóa vận hành nhiều kho (Kho Tổng, Kho Miền Bắc, Kho Miền Nam). Việc quản lý chứng từ nhập xuất gặp rủi ro lớn khi xuất quá số lượng thực tế gây âm kho, chỉnh sửa chứng từ sau lưng kế toán, hoặc rò rỉ đường link phê duyệt dẫn đến duyệt lặp lại nhiều lần.

StockHub được xây dựng nhằm đáp ứng mục tiêu:

  • Kiểm soát số lượng tồn kho chính xác theo từng kho: Quản lý số lượng tồn thực tế (On-hand) và phân bổ (Reserved), cấm mọi giao dịch dẫn đến âm kho.
  • Bảo đảm tính toàn vẹn chứng từ: Chứng từ nhập/xuất/chuyển kho sau khi Kế toán duyệt trở thành nguồn sự thật bất biến (Immutable), mọi điều chỉnh phải thông qua chứng từ bù.
  • Quy trình phê duyệt an toàn, tinh gọn: Nhân viên kho tạo phiếu và cấp phát liên kết duyệt một lần cho Kế toán, Kế toán thao tác phê duyệt nhanh chóng qua web mà không cần đăng nhập rườm rà nhưng vẫn đảm bảo tính bảo mật và duy nhất.

3 Quy tắc bất biến bắt buộc

Quy tắc Ý nghĩa nghiệp vụ Giải pháp kỹ thuật cốt lõi
1. Tồn kho không được âm Không cho phép xuất hoặc điều chuyển số lượng lớn hơn số lượng hàng hiện có tại kho chỉ định. Kiểm tra điều kiện ở Domain Model, khóa lạc quan (RowVersion/Concurrency Token) trong EF Core 10, bọc DB Transaction đảm bảo chống Race Condition.
2. Phiếu đã duyệt không được sửa Phiếu đã được Kế toán duyệt hoặc từ chối là dữ liệu lịch sử tài chính, không ai được quyền sửa đổi hay xóa. Quy tắc chuyển trạng thái State Machine: chỉ trạng thái Draft mới được chỉnh sửa. Chặn ở Application Handler, Domain Validation và Interceptor EF Core.
3. Link duyệt gửi kế toán chỉ dùng 1 lần Đường link chứa token phê duyệt gửi cho Kế toán sau khi đã bấm Duyệt hoặc Từ chối sẽ bị vô hiệu hóa vĩnh viễn. Lưu bảng ApprovalTokens với mã băm an toàn (SHA-256), ghi nhận UsedAt và cập nhật trạng thái phiếu trong 1 Transaction duy nhất. Kiểm tra UsedAt != null sẽ trả về lỗi RFC 9457 (400/410).

Phạm vi & Ngoài phạm vi (Out of Scope)

Nhằm đảm bảo chất lượng cao nhất cho bài tập lớn cá nhân và hoàn thành đúng hạn 100% tiêu chí chấm điểm, dự án phân định rõ ranh giới:

Trong phạm vi (In-Scope) Ngoài phạm vi (Out-of-Scope)
Quản lý 3 vai trò: Admin, WarehouseStaff, Accountant. Quản lý hạn sử dụng (FEFO/FIFO date-tracking), số Lô (Batch/Lot), Serial Number chi tiết.
Quản lý danh mục Kho (đa kho), Sản phẩm, Phiếu nhập, Phiếu xuất, Điều chuyển. Quản lý vị trí ô kệ chi tiết trong kho (Bin/Rack/Shelf location).
Tạo & sao chép liên kết duyệt 1 lần trực tiếp trên giao diện và API (Chế độ Demo nhanh). Tích hợp máy chủ gửi thư ngoài qua SMTP/MailKit (tránh lỗi mạng container).
Lịch sử biến động tồn kho bất biến (StockTransactionHistory). Tích hợp cổng thanh toán trực tuyến hoặc máy in hóa đơn điện tử.
Xác thực JWT + Refresh Token, Swagger UI có nút Authorize. Đa tenant (Multi-tenant SaaS nhiều công ty).
Docker Compose trọn gói, Unit Test có Code Coverage, GitHub Actions CI. Ứng dụng di động Native (chỉ tập trung Web React responsive).

Cấu trúc bộ tài liệu đặc tả

Tài liệu gồm 12 trang chuyên đề và 1 trang quyết định kiến trúc (ADR) được tổ chức theo đúng quy chuẩn AGENTS.md:

  1. Tổng quan (index.html): Bối cảnh, mục tiêu, 3 quy tắc và ranh giới hệ thống.
  2. Hiện trạng (hien-trang.html): Khảo sát điểm xuất phát (Greenfield), cấu trúc hiện có của repo.
  3. Yêu cầu (yeu-cau.html): User stories, Gherkin Given/When/Then chi tiết cho từng vai trò và các ca kiểm thử quy tắc bất biến.
  4. Mô hình miền (mo-hinh-mien.html): Thiết kế Rich Domain Model, Entity, Aggregate, Value Object và sơ đồ trạng thái phiếu (State Diagram SVG).
  5. Các phương án (phuong-an.html): So sánh các giải pháp giải quyết race condition âm kho và token duyệt 1 lần.
  6. Thiết kế API (thiet-ke-api.html): Danh mục endpoint chuẩn RESTful /api/v1, cơ chế Auth Bearer + Refresh Token, chuẩn mã lỗi RFC 9457.
  7. Thiết kế dữ liệu (thiet-ke-du-lieu.html): Sơ đồ ERD SVG, schema 8 bảng, chiến lược Indexing và Concurrency Token.
  8. Mockup giao diện (mockup.html): Wireframe trực quan màn hình quản lý kho, tạo phiếu, cấp link duyệt và màn hình duyệt của Kế toán.
  9. Rủi ro & Migration (rui-ro-migration.html): Phân tích rủi ro đồng thời, rủi ro token và chiến lược migration database.
  10. Tiêu chí nghiệm thu (nghiem-thu.html): Bảng tiêu chí có mã số kiểm chứng được, kịch bản test 3 quy tắc bất biến.
  11. Quyết định đã chốt (cau-hoi.html): Ghi nhận các quyết định Q-01 đến Q-04 đã thống nhất với người dùng.
  12. Lộ trình phân rã (lo-trinh.html): Phân rã theo lát dọc (Vertical Slices) chuẩn bị cho quá trình cài đặt.
  13. ADR-0001 (adr-0001-...html): Ghi nhận quyết định kiến trúc khóa kho và token một lần.
