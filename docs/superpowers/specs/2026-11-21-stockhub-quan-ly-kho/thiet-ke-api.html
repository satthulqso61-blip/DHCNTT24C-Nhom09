6. Thiết kế API RESTful & Cơ chế Xác thực

Đặc tả chuẩn danh mục Endpoints /api/v1, Swagger UI tích hợp Bearer + Refresh Token và chuẩn hóa mã lỗi RFC 9457.

Chuẩn API: Định tuyến RESTful danh từ số nhiều, phiên bản hóa /api/v1, mọi phản hồi lỗi tuân thủ nghiêm ngặt RFC 9457 ProblemDetails, tài liệu hóa tương tác trực tiếp qua Swagger UI.

Cơ chế xác thực: JWT Bearer & Refresh Token

Hệ thống sử dụng cơ chế xác thực kép:

  • Access Token: JWT chứa sub (UserId), email, roles, ký bằng thuật toán HMAC-SHA256, thời hạn sống ngắn (15 phút).
  • Refresh Token: Chuỗi bảo mật ngẫu nhiên lưu tại bảng RefreshTokens (thời hạn 7 ngày). Khi Access Token hết hạn (nhận mã 401), Client tự động gọi endpoint /api/v1/auth/refresh để lấy cặp token mới mà không bắt người dùng đăng nhập lại.
  • Cấu hình Swagger UI: Thêm nút Authorize hỗ trợ nhập token Bearer (Bearer {token}) để giảng viên kiểm thử API trực tiếp trên trình duyệt.

Danh mục Endpoints chi tiết

1. Module Xác thực (/api/v1/auth)

Phương thức Đường dẫn Quyền hạn Mô tả
POST /api/v1/auth/login Public Đăng nhập bằng Email & Mật khẩu. Trả về AccessToken, RefreshToken và Role.
POST /api/v1/auth/refresh Public Làm mới token bằng RefreshToken hợp lệ. Áp dụng cơ chế quay vòng token (Rotation).
GET /api/v1/auth/me Authorize Lấy thông tin tài khoản đang đăng nhập hiện tại và quyền hạn.

2. Module Quản lý Kho (/api/v1/warehouses)

Phương thức Đường dẫn Quyền hạn Mô tả
GET /api/v1/warehouses Tất cả vai trò Lấy danh sách các kho hàng đang hoạt động (kèm tìm kiếm, phân trang).
POST /api/v1/warehouses Admin Tạo mới một kho hàng (Mã kho, Tên kho, Địa chỉ).
PUT /api/v1/warehouses/{id} Admin Cập nhật thông tin kho hàng.

3. Module Tra cứu Tồn kho (/api/v1/inventories)

Phương thức Đường dẫn Quyền hạn Mô tả
GET /api/v1/inventories Tất cả vai trò Tra cứu tồn kho theo từng kho hoặc sản phẩm: QuantityOnHand, QuantityReserved, Available.
GET /api/v1/inventories/history Tất cả vai trò Tra cứu sổ nhật ký biến động tồn kho (Append-Only Audit Trail) theo SKU/Kho.

4. Module Chứng từ kho (/api/v1/vouchers)

Phương thức Đường dẫn Quyền hạn Mô tả
GET /api/v1/vouchers Tất cả vai trò Lấy danh sách phiếu nhập/xuất/chuyển kèm bộ lọc trạng thái (Draft, PendingApproval, Approved, Rejected).
GET /api/v1/vouchers/{id} Tất cả vai trò Xem chi tiết phiếu và danh sách dòng sản phẩm kèm đơn giá.
POST /api/v1/vouchers WarehouseStaff, Admin Tạo phiếu mới ở trạng thái Draft (Kiểm tra tồn kho sơ bộ nếu là phiếu xuất).
PUT /api/v1/vouchers/{id} WarehouseStaff, Admin Cập nhật phiếu nháp. Chặn lỗi 400 nếu Status != Draft (Quy tắc 2).
DELETE /api/v1/vouchers/{id} WarehouseStaff, Admin Xóa phiếu nháp. Chặn lỗi 400 nếu Status != Draft (Quy tắc 2).
POST /api/v1/vouchers/{id}/create-approval-link WarehouseStaff, Admin Chuyển phiếu sang PendingApproval, sinh token 1 lần và trả về URL duyệt (Quy tắc 3).

5. Module Phê duyệt Một lần (/api/v1/approvals)

Phương thức Đường dẫn Quyền hạn Mô tả
GET /api/v1/approvals/verify?token={token} Public (Dựa vào Token) Xác thực token và lấy thông tin chi tiết phiếu cho Kế toán xem trước khi bấm Duyệt. Báo lỗi nếu token đã dùng hoặc hết hạn.
POST /api/v1/approvals/settle Public (Dựa vào Token) Thực thi Duyệt (Approve) hoặc Từ chối (Reject). Đánh dấu UsedAt và vô hiệu hóa token ngay lập tức (Quy tắc 3).

Đặc tả mã lỗi chuẩn RFC 9457 ProblemDetails

Mã HTTP Error Code nghiệp vụ Quy tắc liên quan Mô tả chi tiết trả về client
400 Bad Request INSUFFICIENT_STOCK Quy tắc 1 Tồn kho không đủ để xuất. Trả kèm chi tiết: productId, requested, available.
409 Conflict CONCURRENCY_CONFLICT Quy tắc 1 Dữ liệu tồn kho vừa được cập nhật bởi một phiên làm việc khác. Client vui lòng tải lại và thử lại.
400 Bad Request VOUCHER_IMMUTABLE Quy tắc 2 Phiếu đã ở trạng thái Approved hoặc Rejected, cấm mọi thao tác sửa hoặc xóa.
410 Gone TOKEN_ALREADY_USED Quy tắc 3 Liên kết duyệt này chỉ được sử dụng một lần và đã được Kế toán xác nhận vào lúc [UsedAt].
400 Bad Request TOKEN_EXPIRED Quy tắc 3 Liên kết duyệt đã hết hạn hiệu lực sau 24 giờ. Vui lòng yêu cầu thủ kho sinh liên kết mới.
