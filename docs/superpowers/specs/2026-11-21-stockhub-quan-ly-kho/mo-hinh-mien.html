4. Mô hình miền (Domain Model)

Đặc tả Rich Domain Model, ranh giới Aggregate, Value Object, các quy tắc bất biến và máy trạng thái chứng từ.

Nguyên tắc Rich Domain: Mọi quy tắc kiểm tra tính hợp lệ và biến đổi trạng thái nghiệp vụ (đặc biệt là 3 quy tắc bất biến) nằm trọn vẹn trong các Entity và Aggregate Root của tầng Domain, tuyệt đối không để Anemic Domain Model (không dùng setter public tùy tiện).

Danh sách Aggregate Roots & Entities

1. Aggregate Root: Voucher (Chứng từ kho)

Là đối tượng trung tâm quản lý toàn bộ vòng đời của phiếu nhập kho (Receipt), phiếu xuất kho (Issue) và điều chuyển (Transfer).

  • Định danh: VoucherId (Guid)
  • Thuộc tính:
    • Code: Value Object mã chứng từ (VD: PN-20261121-001, PX-20261121-002).
    • Type: Enum VoucherType (Receipt, Issue, Transfer).
    • Status: Enum VoucherStatus (Draft, PendingApproval, Approved, Rejected).
    • SourceWarehouseId: Guid (Kho xuất/nguồn, rỗng nếu là phiếu nhập).
    • TargetWarehouseId: Guid (Kho nhập/đích, rỗng nếu là phiếu xuất).
    • Notes: Ghi chú lý do xuất nhập.
    • CreatedByUserId, CreatedAt, ApprovedByUserId, ApprovedAt, RejectionReason.
  • Entity con: IReadOnlyCollection<VoucherDetail> Details (Danh sách các dòng hàng gồm ProductId, Quantity, UnitPrice).
  • Hành vi nghiệp vụ (Methods):
    • AddLine(productId, quantity, unitPrice): Kiểm tra Status == Draft, số lượng > 0. Nếu vi phạm ném VoucherImmutableException.
    • SubmitForApproval(): Kiểm tra danh sách mặt hàng không rỗng. Chuyển trạng thái từ Draft sang PendingApproval.
    • Approve(approverUserId): Kiểm tra Status == PendingApproval. Đổi trạng thái sang Approved, gán ApprovedAt = UtcNow. Phát sinh Domain Event VoucherApprovedDomainEvent để kích hoạt cập nhật tồn kho.
    • Reject(approverUserId, reason): Kiểm tra Status == PendingApproval. Đổi trạng thái sang Rejected, ghi nhận lý do. Phát sinh Domain Event VoucherRejectedDomainEvent.

2. Aggregate Root: Inventory (Tồn kho)

Quản lý số lượng tồn của một mặt hàng cụ thể tại một kho cụ thể.

  • Định danh kép (Composite Key): WarehouseId + ProductId.
  • Thuộc tính:
    • QuantityOnHand: Số lượng thực tế trong kho.
    • QuantityReserved: Số lượng đã được giữ chỗ cho các phiếu xuất đang chờ duyệt.
    • RowVersion: Concurrency Token kiểu byte array (hoặc uint xmin trên PostgreSQL) để phát hiện xung đột ghi đồng thời.
  • Hành vi nghiệp vụ (Bảo vệ Quy tắc 1):
    • EnsureSufficientStock(requestedQty): Kiểm tra (QuantityOnHand - QuantityReserved) >= requestedQty. Nếu không thỏa mãn, ném InsufficientStockException.
    • DeductStock(quantity): Trừ trực tiếp QuantityOnHand -= quantity. Đảm bảo điều kiện bất biến QuantityOnHand >= 0 luôn luôn đúng sau phép tính.
    • AddStock(quantity): Cộng QuantityOnHand += quantity khi phiếu nhập được duyệt.

3. Entity: ApprovalToken (Mã duyệt bảo mật một lần)

Quản lý quyền truy cập và tính sử dụng một lần của liên kết gửi Kế toán (Quy tắc 3).

  • Định danh: TokenId (Guid).
  • Thuộc tính:
    • VoucherId: Tham chiếu đến chứng từ cần duyệt.
    • TokenHash: Chuỗi băm SHA-256 của token ngẫu nhiên bảo mật (để chống lộ token nếu bị đọc trộm DB).
    • ExpiresAt: Thời điểm hết hạn (UTC), mặc định $Now + 24$ giờ.
    • UsedAt: Thời điểm token được sử dụng (nullable UTC).
    • CreatedAt: Thời điểm khởi tạo.
  • Hành vi nghiệp vụ:
    • Consume(): Kiểm tra nếu UsedAt.HasValue thì ném ngay ApprovalTokenAlreadyUsedException; nếu ExpiresAt < DateTime.UtcNow thì ném ApprovalTokenExpiredException. Nếu hợp lệ, gán UsedAt = DateTime.UtcNow.

Value Objects (Đối tượng giá trị)

Value Object Thuộc tính Quy tắc bất biến
VoucherCode string Value Định dạng {TYPE}-{yyyyMMdd}-{XXXX} (VD: PN-20261121-0001). Không được rỗng, không chứa ký tự đặc biệt ngoài gạch nối.
SKU string Value Từ 3 đến 30 ký tự, viết hoa, chỉ gồm chữ cái, số và dấu gạch nối (VD: LAPTOP-DELL-5520).
Money decimal Amount, string Currency Số tiền Amount >= 0, làm tròn 2 chữ số thập phân, tiền tệ mặc định VND.

Sơ đồ máy trạng thái chứng từ (Voucher State Diagram)

Sơ đồ sau minh họa luồng chuyển trạng thái và các rào cản ngăn chặn vi phạm 3 quy tắc:

Hiện thực các quy tắc bất biến trong Code

// Minh họa logic nghiệp vụ bất biến tại Domain Entity Voucher
public sealed class Voucher : AggregateRoot<Guid>
{
    private readonly List<VoucherDetail> _details = new();
    public IReadOnlyCollection<VoucherDetail> Details => _details.AsReadOnly();
    public VoucherStatus Status { get; private set; } = VoucherStatus.Draft;

    public void AddDetail(Guid productId, decimal quantity, decimal unitPrice)
    {
        if (Status != VoucherStatus.Draft)
        {
            throw new VoucherImmutableException(
                $"Phiếu {Code} đang ở trạng thái {Status}, không được phép sửa đổi theo Quy tắc 2.");
        }
        if (quantity <= 0)
        {
            throw new DomainRuleException("Số lượng hàng hóa phải lớn hơn 0.");
        }
        _details.Add(new VoucherDetail(Id, productId, quantity, unitPrice));
    }

    public void Approve(Guid accountantUserId)
    {
        if (Status != VoucherStatus.PendingApproval)
        {
            throw new InvalidVoucherStateException(
                $"Chỉ phiếu đang chờ duyệt mới có thể phê duyệt. Trạng thái hiện tại: {Status}.");
        }
        Status = VoucherStatus.Approved;
        ApprovedByUserId = accountantUserId;
        ApprovedAt = DateTime.UtcNow;

        // Bắn domain event cập nhật kho và lưu audit log
        AddDomainEvent(new VoucherApprovedDomainEvent(Id, Type, SourceWarehouseId, TargetWarehouseId, _details));
    }
}
