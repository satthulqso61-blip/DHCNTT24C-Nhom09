12. Lộ trình Triển khai & Phân rã Công việc

Kế hoạch triển khai theo từng lát dọc (Vertical Slice Architecture), thứ tự phụ thuộc và tiêu chí hoàn thành từng giai đoạn.

Phương pháp tiếp cận: Phát triển theo từng Lát dọc (Vertical Slice): Mỗi lát đi xuyên suốt từ Domain $\rightarrow$ Application (CQRS) $\rightarrow$ Infrastructure (EF Core) $\rightarrow$ WebApi Endpoint $\rightarrow$ Test, đảm bảo tính năng chạy độc lập được kiểm chứng ngay trước khi chuyển sang lát tiếp theo.

Các giai đoạn triển khai (Phases)

Giai đoạn 1: Nền tảng Backend, Auth & Swagger (Slice 1)

Thiết lập khung dự án Clean Architecture và cơ chế định danh phân quyền.

  • Khởi tạo Solution .NET 10: Domain, Application, Infrastructure, WebApi và các dự án Test tương ứng.
  • Cài đặt MediatR, FluentValidation, EF Core 10, Serilog.
  • Hiện thực Entity User, RefreshToken; Dịch vụ cấp phát JWT Access Token và Refresh Token Rotation.
  • Cấu hình Swagger UI tích hợp nút Authorize Bearer JWT.
  • Cấu hình Middleware xử lý lỗi toàn cục chuẩn RFC 9457 ProblemDetails.
  • Tiêu chí hoàn thành: Đăng nhập và Refresh Token thành công trên Swagger với 3 tài khoản mẫu.

Giai đoạn 2: Danh mục Kho & Hàng hóa (Slice 2)

Quản lý dữ liệu nền tảng cho kho hàng và sản phẩm.

  • Domain & EF Core Entity: Warehouse, Product.
  • Features CQRS: CreateWarehouseCommand, GetWarehousesQuery, CreateProductCommand, GetProductsQuery.
  • Cấu hình Soft Delete (IsDeleted) qua EF Core SaveChanges Interceptor.
  • Tiêu chí hoàn thành: Tạo được 3 kho hàng (Kho Tổng, Miền Bắc, Miền Nam) và 15 sản phẩm mẫu qua API.

Giai đoạn 3: Chứng từ kho & Bảo vệ Quy tắc 1 + Quy tắc 2 (Slice 3)

Cài đặt lõi nghiệp vụ kiểm soát tồn kho và bất biến chứng từ.

  • Domain Entity: Voucher, VoucherDetail, Inventory.
  • Bảo vệ Quy tắc 1 (Tồn kho không âm): Cấu hình Concurrency Token RowVersion trên Inventory; Viết logic DeductStock kiểm tra số lượng tồn khả dụng; Thêm DB Check Constraint.
  • Bảo vệ Quy tắc 2 (Phiếu đã duyệt cấm sửa): State Machine chặn sửa/xóa khi Status != Draft; Viết Unit Test assert ngoại lệ khi vi phạm.
  • Features CQRS: CreateDraftVoucherCommand, UpdateDraftVoucherCommand, DeleteDraftVoucherCommand, GetVouchersQuery.
  • Tiêu chí hoàn thành: Viết Unit Test và Integration Test chứng minh không thể sửa phiếu đã duyệt và không thể xuất kho âm.

Giai đoạn 4: Phê duyệt 1 lần & Audit Trail - Quy tắc 3 (Slice 4)

Hoàn thiện cơ chế liên kết phê duyệt cho Kế toán và sổ cái lịch sử.

  • Domain Entity: ApprovalToken, StockTransactionHistory.
  • Bảo vệ Quy tắc 3 (Link duyệt 1 lần):
    • Command CreateApprovalLinkCommand: Chuyển phiếu sang PendingApproval, sinh token SHA-256, trả về URL.
    • Command SettleVoucherApprovalCommand: Kế toán duyệt hoặc từ chối; cập nhật phiếu, kho, và gán UsedAt = UtcNow trong 1 DB Transaction.
    • Kiểm tra nếu token đã có UsedAt thì ném lỗi 410 Gone TOKEN_ALREADY_USED.
  • Ghi nhật ký biến động kho Append-Only vào bảng StockTransactionHistory.
  • Tiêu chí hoàn thành: Thao tác duyệt thành công lần 1, thử duyệt lại lần 2 bị chặn hoàn toàn.

Giai đoạn 5: Phát triển Giao diện React SPA (Slice 5)

Dựng giao diện người dùng React 19 + TypeScript + Tailwind CSS.

  • Khởi tạo Vite React App, cài đặt Tailwind CSS, React Router, TanStack Query, React Hook Form, Zod.
  • Cấu hình lib/http.ts: Axios Interceptor tự động gắn Bearer Token và tự động refresh token khi gặp 401.
  • Màn hình Đăng nhập & Đổi vai trò nhanh (phục vụ video demo).
  • Màn hình Quản lý kho, Danh sách chứng từ kho kèm nút "Tạo & Sao chép liên kết duyệt".
  • Màn hình Kế toán duyệt phiếu 1 lần: Xem bảng kê, nút Phê duyệt / Từ chối.
  • Màn hình Báo lỗi thân thiện khi link duyệt đã hết hạn hoặc đã được sử dụng.
  • Tiêu chí hoàn thành: Giao diện hoàn chỉnh, hiển thị tốt trên Desktop và Mobile.

Giai đoạn 6: Docker Compose, Kiểm thử & CI/CD (Slice 6)

Đóng gói toàn bộ sản phẩm và thiết lập tự động hóa chất lượng.

  • Viết Dockerfile tối ưu đa tầng (Multi-stage build) cho Backend WebApi và Frontend React.
  • Viết docker-compose.yml liên kết Backend, Frontend và Database PostgreSQL.
  • Cấu hình tự động Migrate Database và nạp Seed Data mẫu khi container khởi động.
  • Viết trọn bộ Unit Test & Integration Test (kiểm thử 3 quy tắc bất biến), đo độ bao phủ đạt $\ge 80\%$ bằng Coverlet.
  • Tạo GitHub Actions Workflow: .github/workflows/ci.yml tự động chạy build và test.
  • Tiêu chí hoàn thành: Chạy thành công docker compose up --build từ terminal sạch; CI xanh 100%.
