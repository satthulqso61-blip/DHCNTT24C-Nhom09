7. Thiết kế Cơ sở Dữ liệu & Mô hình ERD

Đặc tả lược đồ cơ sở dữ liệu quan hệ, chỉ mục Index, cơ chế Concurrency Token và bảo đảm toàn vẹn tham chiếu.

Chuẩn lưu trữ: Cơ sở dữ liệu quan hệ (PostgreSQL / SQL Server), toàn bộ khóa chính sử dụng kiểu Guid (UUIDv7 hoặc Sequential Guid) tối ưu phân tán và bảo mật; Tiền tệ lưu kiểu decimal(18,2); Thời gian đồng nhất chuẩn UTC.

Sơ đồ thực thể liên kết (ERD Diagram)

Sơ đồ quan hệ giữa 9 bảng thực thể chính trong hệ thống:

Chi tiết lược đồ bảng & Chỉ mục (Indexes)

1. Bảng Inventories (Trọng tâm Quy tắc 1)

Lưu trữ số lượng tồn của từng mặt hàng tại mỗi kho. Sử dụng khóa phức hợp và Concurrency Token để chống race condition.

Cột Kiểu dữ liệu Ràng buộc Ý nghĩa
WarehouseId Guid PK, FK Warehouses(Id) Kho lưu trữ hàng hóa.
ProductId Guid PK, FK Products(Id) Sản phẩm tương ứng.
QuantityOnHand decimal(18,3) NOT NULL, CHECK (>= 0) Số lượng thực tế có trong kho. Ràng buộc CHECK DB bảo vệ Quy tắc 1.
QuantityReserved decimal(18,3) NOT NULL, DEFAULT 0 Số lượng đã được giữ cho các phiếu chờ duyệt.
RowVersion byte[] (hoặc xmin) Concurrency Token Phát hiện xung đột khi nhiều người cùng xuất 1 mặt hàng cùng thời điểm.

2. Bảng Vouchers (Trọng tâm Quy tắc 2)

Cột Kiểu dữ liệu Ràng buộc Ý nghĩa
Id Guid PK Khóa chính chứng từ.
Code varchar(30) NOT NULL, UNIQUE INDEX Mã phiếu không trùng (VD: PX-20261121-0001).
Type int NOT NULL 0: Nhập kho (Receipt), 1: Xuất kho (Issue), 2: Điều chuyển (Transfer).
Status int NOT NULL 0: Draft, 1: PendingApproval, 2: Approved, 3: Rejected.
SourceWarehouseId Guid? FK Warehouses(Id) Kho xuất hàng (dành cho phiếu xuất hoặc chuyển).
TargetWarehouseId Guid? FK Warehouses(Id) Kho nhập hàng (dành cho phiếu nhập hoặc chuyển).
ApprovedByUserId Guid? FK Users(Id) Kế toán thực hiện duyệt.
ApprovedAt timestamp (UTC)? Nullable Thời điểm duyệt phiếu.

3. Bảng ApprovalTokens (Trọng tâm Quy tắc 3)

Cột Kiểu dữ liệu Ràng buộc Ý nghĩa
Id Guid PK Khóa chính token.
VoucherId Guid NOT NULL, FK Vouchers(Id) Phiếu cần được duyệt.
TokenHash varchar(64) NOT NULL, UNIQUE INDEX Băm SHA-256 của token bí mật gửi cho Kế toán.
ExpiresAt timestamp (UTC) NOT NULL Thời điểm hết hạn hiệu lực (mặc định $CreatedAt + 24h$).
UsedAt timestamp (UTC)? Nullable Thời điểm token đã được Kế toán bấm Duyệt/Từ chối. Khóa Quy tắc 3: nếu != null thì từ chối.

4. Bảng StockTransactionHistory (Sổ cái biến động kho bất biến)

Bảng hoạt động theo nguyên lý Append-Only. Nghiêm cấm mọi lệnh UPDATE hoặc DELETE (được bảo vệ bằng Application Rule và EF Core Interceptor).

Cột Kiểu dữ liệu Ràng buộc Ý nghĩa
Id Guid PK Định danh bản ghi biến động.
VoucherId Guid FK Vouchers(Id) Căn cứ chứng từ phê duyệt.
WarehouseId Guid FK Warehouses(Id) Kho có lượng hàng thay đổi.
ProductId Guid FK Products(Id) Mặt hàng biến động.
ChangeQuantity decimal(18,3) NOT NULL Số lượng biến động (+ đối với nhập, - đối với xuất).
BalanceAfter decimal(18,3) NOT NULL, >= 0 Số lượng tồn sau khi thực hiện giao dịch.
OccurredAt timestamp (UTC) NOT NULL Thời điểm giao dịch được ghi nhận.

Chiến lược Indexing tối ưu hiệu năng

  • CREATE UNIQUE INDEX IX_Vouchers_Code ON Vouchers (Code);: Tra cứu phiếu theo mã tức thì.
  • CREATE INDEX IX_Vouchers_Status_Warehouse ON Vouchers (Status, SourceWarehouseId, TargetWarehouseId);: Tối ưu bộ lọc danh sách phiếu.
  • CREATE UNIQUE INDEX IX_ApprovalTokens_Hash ON ApprovalTokens (TokenHash);: Tra cứu token duyệt cực nhanh trong $O(1)$.
  • CREATE INDEX IX_StockHistory_Product_Warehouse ON StockTransactionHistory (ProductId, WarehouseId, OccurredAt DESC);: Truy vấn sao kê biến động kho cho Kế toán và Thủ kho.
