10. Tiêu chí Nghiệm thu (Acceptance Criteria)

Bảng tiêu chí kiểm thử có đánh số, đúng/sai rõ ràng, làm căn cứ nghiệm thu đồ án và quay video demo.

Nguyên tắc nghiệm thu: Mỗi tiêu chí bắt buộc phải có bài kiểm tra thực tế (Unit Test, Integration Test hoặc kịch bản chạy thật trên UI/API) có kết quả Nhị phân (Pass / Fail rõ ràng).

Nhóm 1: Nghiệm thu 3 Quy tắc bắt buộc (Trọng số 50%)

Mã TC Tiêu chí kiểm thử Thao tác thực hiện Kết quả mong đợi (Pass) Kết quả thực tế
TC-01 Chặn xuất quá tồn kho (Quy tắc 1) Tồn kho SKU A hiện có 5 cái. Lập phiếu xuất với số lượng 6 cái. API từ chối với HTTP 400 kèm mã INSUFFICIENT_STOCK; giao diện báo đỏ cảnh báo thiếu hàng; tồn kho giữ nguyên 5. Chờ kiểm thử
TC-02 Chống âm kho khi xuất đồng thời (Quy tắc 1) Tồn kho có 10 cái. Chạy Integration Test bắn 20 requests xuất kho song song (mỗi request 1 cái). Đúng 10 request thành công, 10 request bị từ chối; tồn kho sau cùng bằng đúng 0, tuyệt đối không bị âm; không xảy ra Deadlock. Chờ kiểm thử
TC-03 Cấm sửa phiếu đã duyệt (Quy tắc 2) Lấy ID phiếu ở trạng thái Approved, gửi lệnh HTTP PUT/DELETE sửa thông tin phiếu. Hệ thống trả về HTTP 400 kèm chi tiết VOUCHER_IMMUTABLE; cơ sở dữ liệu không bị thay đổi. Chờ kiểm thử
TC-04 Tạo link duyệt 1 lần và sao chép (Quy tắc 3) Trên phiếu nháp, bấm "Tạo liên kết duyệt". Phiếu chuyển sang PendingApproval; pop-up hiện URL chứa token bảo mật 64 ký tự; bấm sao chép lưu vào clipboard. Chờ kiểm thử
TC-05 Kế toán duyệt thành công qua link lần 1 (Quy tắc 3) Mở URL duyệt trên trình duyệt, kiểm tra thông tin mặt hàng và bấm "Xác nhận Phê duyệt". Phiếu chuyển thành Approved; tồn kho được trừ/cộng chính thức; bảng token cập nhật UsedAt = UtcNow. Chờ kiểm thử
TC-06 Chặn tái sử dụng link duyệt lần 2 (Quy tắc 3) Tải lại (F5) trang duyệt vừa thao tác hoặc paste lại URL cũ vào tab mới và thử bấm duyệt. API trả về HTTP 410 Gone kèm mã TOKEN_ALREADY_USED; màn hình hiển thị cảnh báo đỏ từ chối; tồn kho không bị trừ thêm lần nữa. Chờ kiểm thử

Nhóm 2: Nghiệm thu Phân quyền & Chức năng (Trọng số 25%)

Mã TC Tiêu chí kiểm thử Thao tác thực hiện Kết quả mong đợi (Pass) Kết quả thực tế
TC-07 Xác thực 3 vai trò người dùng Đăng nhập lần lượt bằng 3 tài khoản Admin, WarehouseStaff, Accountant. Nhận JWT Token hợp lệ; giao diện hiển thị đúng menu tính năng tương ứng với vai trò. Chờ kiểm thử
TC-08 Quản lý nhiều kho hàng Tạo danh mục gồm 3 kho: Kho Tổng, Kho Miền Bắc, Kho Miền Nam. Danh sách hiển thị chính xác; tồn kho của cùng 1 SKU được tách biệt rõ ràng theo từng kho. Chờ kiểm thử
TC-09 Truy vết lịch sử biến động (Audit Trail) Thực hiện 1 chuỗi thao tác: Nhập kho $\rightarrow$ Xuất kho $\rightarrow$ Điều chuyển kho. Sổ cái StockTransactionHistory ghi lại đầy đủ từng dòng biến động kèm số dư sau giao dịch và ID chứng từ. Chờ kiểm thử

Nhóm 3: Tiêu chuẩn Kỹ thuật Bắt buộc (Trọng số 25%)

Mã TC Tiêu chuẩn kỹ thuật Cách kiểm tra Kết quả mong đợi (Pass) Kết quả thực tế
TC-10 Swagger UI hỗ trợ JWT + Refresh Token Mở /swagger, bấm Authorize, dán Bearer token và test gọi API bảo mật. Gọi thành công API có [Authorize]; có endpoint refresh token hoạt động. Chờ kiểm thử
TC-11 Chạy trọn bộ bằng Docker Compose Mở terminal chạy lệnh: docker compose up --build trên môi trường sạch. Backend WebApi, Frontend React và Database cùng khởi động thành công, tự động nạp seed data mẫu. Chờ kiểm thử
TC-12 Độ bao phủ Unit Test (Code Coverage) Chạy lệnh kiểm thử với coverlet: dotnet test /p:CollectCoverage=true. Toàn bộ test vượt qua (100% Pass), tổng tỷ lệ bao phủ code (Coverage) đạt $\ge 80\%$. Chờ kiểm thử
TC-13 Tự động hóa CI (GitHub Actions) Đẩy commit lên GitHub nhánh chính. Workflow GitHub Actions tự động kích hoạt và hoàn thành với trạng thái Xanh (Build & Test Passed). Chờ kiểm thử
